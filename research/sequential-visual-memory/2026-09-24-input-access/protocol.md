# T29: training-only identity access in transparent inputs

Owning issue: [#58](https://github.com/akhmialeuski/fly-connectome-lab/issues/58). Parent: the negative [T28 identity diagnostic](../2026-09-24-identity-access/results.md). This protocol, [cohort](cohort.json), and [schedule](schedule.json) are committed before T29 fitting or held-out score inspection. They cannot be amended after viewing outcomes; any correction is a new, named attempt and an issue follow-up.

## Question and cohort

T28's raw one-nearest-neighbor controls used only two images per identity and three raster windows. Their 3/40 pixel and 3/40 encoded-current scores could not identify a fly-specific information loss. T29 tests whether the **unchanged** transparent inputs support identity with more training photographs and a fixed, simple linear diagnostic. It neither simulates nor trains the fly model and makes no sequential-memory claim.

Use `configs/celeba-smoke.yaml` without overrides, original 20-identity CelebA training membership from the archived #50 study, original 128-pixel five-landmark alignment, original 16-step raster trajectory, and original sparse signed-RGB encoder. The source membership, effective config, aligned-image preprocessing key, dataset fingerprint, and every selected source JPEG and aligned RGB-array SHA-256 are frozen in `cohort.json`. Its selection algorithm ranks the 14 **training** samples per identity by `(stable_int(sample_id), sample_id)`; ranks 0–9 are fit references and ranks 10–13 are held-out **training** queries. Thus there are exactly 200 fit and 80 query photographs, 20 identities, no class imbalance, and no random split search. T27/T28 photographs can recur. This is exploratory training-only assessment, not independent or untouched confirmation. Validation, historical test, and reserve labels/scores must not affect fitting or decisions; no source or aligned image bytes enter the run/archive.

`schedule.json` freezes the exact ordered fit/query IDs, five stratified shuffled CV folds, original 0 seed and four-value C grid, PCA cap, solver budget and tolerance, complete window order, and practical advancement gate. The source study used the same readout family and fold-local preprocessing. The primary feature representations are (a) all 16 raster RGB windows flattened to float32 and divided by 255, and (b) all 16 sparse encoded-current vectors in the original selected-neuron order, flattened. No augmentation, learned feature extractor, per-window selection, or hand-picked mask is permitted. The sparse encoder itself is fixed and does not fit identities.

## Fitting, controls, and decision

For each representation separately, use `StandardScaler -> PCA(60) -> LogisticRegression` with existing `fit_classifier`: five stratified folds, seed 0, C values 0.01/0.1/1/10, tolerance 1e-6, max 50,000 iterations, one BLAS thread. Fit scaler/PCA **inside each CV fold**. Choose C by mean fit-fold accuracy, breaking ties toward smaller C, then refit on the same 200 fit photographs. A convergence warning is a failed fit, not a score. Save selected C, every CV mean, training predictions, held-out query predictions with probabilities, top-1/top-5, natural-log loss, iterations, finite-feature checks, fitted scaler/PCA/classifier arrays, exact source hashes, and resource use. Freeze and inventory each completed or failed attempt. The held-out query labels must not be passed to fitting/CV or used for candidate selection.

The predeclared gate advances only if **both** representations achieve at least 20/80 (25%) held-out training-query top-1 and each log loss is strictly below `ln(20) ~= 2.995732274`. Uniform 20-way choice is 5%. Report per-identity counts and uncertainty as descriptive analysis; these dependent training-cohort photographs do not support a population-level significance claim. If either representation fails, first investigate source, alignment, window geometry, input encoding, and metric effects. If both pass, freeze a separate matched neural-response/recognition study before changing fly dynamics or constrained plasticity. A favorable T29 input score alone cannot prove a fly-network bottleneck: neural and input assessments must be matched for cohort, windows, readout, and noise.

Stop the campaign at 60 minutes wall time or 12 GiB peak RSS, retaining any failure manifest. Do not silently shrink the cohort, shorten the raster sequence, change PCA/C/solver settings, or select a better representation after seeing scores. For a solver or resource failure, record the root cause and preregister any retry as a new attempt. Publish all attempts, results, limitations, and next decision in #58 and roadmap #39. Archive numeric evidence in this sibling directory and verify every archived byte, including Git LFS coefficients, from a fresh remote clone. Keep the implementation PR stacked on unmerged #57.
