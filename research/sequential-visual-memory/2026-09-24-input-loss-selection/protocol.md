# T30: fit-only log-loss selection for transparent input controls

Owning issue [#60](https://github.com/akhmialeuski/fly-connectome-lab/issues/60). Parent negative-gate study [T29](../2026-09-24-input-access/results.md). This protocol and its [machine-readable schedule](schedule.json) are committed **before** T30 fits or out-of-fold log losses are calculated. The T29 80 query labels and scores are already inspected, so any later score on them is descriptive development evidence, never fresh confirmation.

## Frozen sources and fits

Reuse the exact [T29 cohort](../2026-09-24-input-access/cohort.json) and its 200 fit / 80 query roles, [T29 schedule](../2026-09-24-input-access/schedule.json) and five exact 160/40 stratified fit folds, and unchanged `configs/celeba-smoke.yaml`. Verify their file hashes, all 280 source JPEG/aligned-image hashes, parent A1 manifest/report digests, original encoder/brain hashes, and original 16 raster windows before fitting. No validation, historical test, or reserve photograph enters selection or scoring. Do not archive source or transformed image arrays.

For each of two prespecified representations—flattened 16-window RGB pixels scaled to `[0,1]`, and original sparse encoded-current vectors—fit each fixed C in `[0.01, 0.1, 1, 10]` on each of the five T29 training folds. Fit `StandardScaler` and PCA(60) **inside each fold** and use the same `LogisticRegression` implementation, seed 0, tolerance `1e-6`, 50,000-iteration maximum, and one BLAS thread as T29. A convergence warning or source mismatch fails the attempt; do not drop a fold or swap solvers. Store all 1,600 out-of-fold probability rows, per-C/fold iterations, fold accuracy/log loss, and feature/model source hashes. For each representation and C, pool the 200 out-of-fold rows, then compute top-1, top-5, and natural-log loss with the fixed 20-class order. Select C by the **minimum pooled OOF log loss**, breaking an exact tie toward smaller C. Do not access the 80 query labels to choose C, adjust features, or decide the primary gate.

The predeclared measurement gate passes only if **both** chosen representations achieve at least 25% pooled OOF top-1 and pooled OOF log loss strictly below `ln(20)`. It is a practical fit-cohort diagnostic, not an independent population significance test. If it passes, the next study may freeze a matched neural comparison before modifying fly dynamics or plasticity. If it fails, report the weak metric and investigate geometry/readout further. No T29 gate is revised by this study.

After the two C choices and OOF gate are fixed, refit each selected model on all 200 fit photographs and score the same 80 previously inspected T29 queries once. Save full scaler/PCA/classifier coefficients, fit/query probabilities, class metrics, reliability bins, and comparison to the original T29 accuracy-selected models. Query outcomes are descriptive and cannot override the OOF gate. The 200 fit photographs have also been used in T29, so OOF metrics remain exploratory; later confirmation must use genuinely untouched data with a frozen protocol.

Retain all failed and completed attempt directories under `FLYSTATE_HOME`; stop at 60 minutes wall time or 12 GiB peak RSS, and report any breach. Publish protocol, all candidate metrics, failures, outcome, and limitations in #60 and roadmap #39. Archive exact numeric evidence in this new dated sibling with NPZ through Git LFS and independently verify every archived byte from a fresh GitHub clone. Keep the PR stacked on unmerged #59.
